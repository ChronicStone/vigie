The **Tasks** screen answers three questions in order: is work flowing, is it succeeding, and are the workers alive.

![The Tasks screen: every task kind with its attempts over time and failure rate](/screens/tasks.png)
_Tasks: each kind with its attempts over time, failures in red, and the reason behind them._


- **Flow.** How many tasks are due, how long the oldest has waited, and which kinds run late. Fed by the `vigie.tasks.backlog` and `vigie.tasks.oldest_due_age` gauges, and by `lateAfterSeconds` in your [catalog](/docs/definitions/catalog).
- **Execution.** Failure rate per kind, the codes behind failures, and every skip and retry with its reason.
- **Liveness.** Which workers reported recently, and attempts that started but never finished because their worker died.

Each run has its own page: every attempt, its outcome, the trace of each try, the queries and external calls it made, and, when your app's database is connected, the row as it is now.

## Sending tasks

| From | How |
|---|---|
| Adonis | [`task()`](/docs/connect/adonis#background-tasks) |
| NestJS | [`@VigieTask()`](/docs/connect/nestjs#background-jobs) |
| Anything else | A wide event with `task.kind` and `taskOutcome.type`. See [the contract](/docs/connect/any-stack#the-wide-event-contract). |

## Acting on tasks

With `VIGIE_APP_API_URL` set, the run page offers **Requeue**, **Cancel** and **Run now**. Vigie calls your app's API as the person who clicked, so your app keeps the permission checks. Agents with a write token can do the same with `requeue_task`, `cancel_task` and `bulk_task_action`.

With `VIGIE_APP_DATABASE_URL` set to a read-only role, Vigie reads queued tasks straight from your app's database. See [Configuration](/docs/self-hosting/configuration).
