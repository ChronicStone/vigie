The **Tasks** screen answers three questions in order: is work flowing, is it succeeding, and are the workers alive.

![The Tasks screen: every task kind with its attempts over time and failure rate](/screens/tasks.png)
_Tasks: each kind with its attempts over time, failures in red, and the reason behind them._


- **Flow.** How many tasks are due, how long the oldest has waited, and which kinds run late. Fed by the `vigie.tasks.backlog` and `vigie.tasks.oldest_due_age` gauges, and by `lateAfterSeconds` in your [catalog](/docs/definitions/catalog).
- **Execution.** Failure rate per kind, the codes behind failures, and every skip and retry with its reason.
- **Liveness.** Which workers reported recently, and attempts that started but never finished because their worker died.

Each run has its own page: every attempt, its outcome, the trace of each try, the queries and external calls it made, and, when your app's database is connected, the row as it is now.

## Sending tasks

| From | How |
|---|---|
| Adonis | [`task()`](/docs/connect/adonis#background-tasks) |
| NestJS | [`@VigieTask()`](/docs/connect/nestjs#background-jobs) |
| Anything else | A wide event with `task.kind` and `taskOutcome.type`. See [the contract](/docs/connect/any-stack#the-wide-event-contract). |

## Acting on tasks

The run page can offer **Requeue**, **Run now** and **Cancel**, each with a reason that your app records. Vigie calls your app's task API (`POST /v1/tasks/<id>/actions/<action>`) with the signed-in person's own app token, so your app keeps its permission checks. That needs both:

- `VIGIE_APP_API_URL`, your app's API;
- single sign-on against your app (`VIGIE_OIDC_*`), so Vigie holds each person's token. See [Configuration](/docs/self-hosting/configuration#sign-in).

Without them, a failed run shows a **Requeue in** button, with your app's name, that opens your app's task screen (`VIGIE_APP_URL/admin/tasks`, or `VIGIE_APP_TASKS_URL`; the name is `VIGIE_APP_NAME`).

Agents cannot act on tasks with a machine token: `requeue_task`, `cancel_task` and the others are not offered over MCP when task actions are off, and refuse a machine token when they are on, because there is no person to act as. `bulk_task_action` only stores a dry run for a person to confirm.

With `VIGIE_APP_DATABASE_URL` set to a read-only role, Vigie also reads queued, waiting and held tasks straight from your app's database, and the run page shows the row as it is now. See [Configuration](/docs/self-hosting/configuration#your-app).
