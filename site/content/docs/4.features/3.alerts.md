title: Alerts and notifications
description: Alerts evaluated every 30 seconds, grouped into one message with the errors behind them and what to do.

Create alerts on the **Alerts** screen, with a live preview of what would have fired over the last days, or in code with [`defineAlert`](/docs/definitions/alerts). An agent can turn an alert made in the app into code with `export_alert_as_code`.

Alerts watch one environment: production on a server (the first of `VIGIE_ENVS`), or the one in `VIGIE_ALERT_ENV`.

## Channels

Add channels on **Settings, Notification channels**:

| Channel | Needs |
|---|---|
| Slack | An incoming webhook, or `VIGIE_SLACK_WEBHOOK`. |
| Discord | A webhook URL. |
| Email | `VIGIE_SMTP_URL` (an SMTP URL such as `smtp://user:pass@mail.example.com:587`) and `VIGIE_MAIL_FROM`. |
| Webhook | A URL. Signed following the Standard Webhooks spec. |
| Your own | [`defineChannel`](/docs/definitions/more#channels). |

On a server, webhook URLs must use `https`. A webhook channel gets its own signing secret when you add it: each post carries `webhook-id`, `webhook-timestamp` and `webhook-signature` headers, which any Standard Webhooks library verifies.

With no channel at all, `VIGIE_SLACK_WEBHOOK` is used when set. **Send a test** posts a sample alert to every channel, so you can see it before you need it, and says how many received it.

## What a message says

Alerts that fire within 30 seconds of each other (`VIGIE_ALERT_GROUP_MS`) go out as one message. It leads with a sentence, not a metric: "Invoices are not reaching Invoxa", from your [error renderers](/docs/definitions/error-renderers). It lists the errors behind it with their why and fix, and links to the screen to open. When it stops, a second message says so.

## Linear

Set `VIGIE_LINEAR_API_KEY` and `VIGIE_LINEAR_TEAM_ID` to add **Create Linear issue** on every issue, with the error, its occurrences and its trace.
