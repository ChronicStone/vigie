---
title: Alerts
description: defineAlert watches error rates, latency, tasks, metrics, missing activity or any SQL, every 30 seconds.
---

```ts [definitions/alerts/acme.ts]
import { defineAlert } from '@vigiejs/sdk'

export const checkoutP95 = defineAlert({
  id: 'checkout-p95',
  name: 'Checkout slow',
  family: 'Endpoint',
  when: { source: 'route-p95', method: 'POST', route: '/orders/:id/checkout', minRequests: 20 },
  above: 2000,
  window: '10m',
  unit: 'ms',
})

export const noPayments = defineAlert({
  id: 'no-payments',
  name: 'No payments ingested',
  family: 'No activity',
  when: { source: 'absence', taskKind: 'paynest.payment.ingest' },
  below: 1,
  window: '30m',
  quiet: { from: '00:00', to: '07:00', timezone: 'Europe/Paris' },
})
```

## What to watch

| `when.source` | Value |
|---|---|
| `request-error-rate` | Share of requests that answered 5xx, in %. |
| `route-p95` | p95 duration of one route, or of every route. `minRequests` ignores quiet windows. |
| `task-failure-rate` | Share of failed task attempts, in %, for one `kind` or all. |
| `oldest-due` | Age of the oldest task waiting for a worker, in seconds. |
| `absence` | Attempts of a task kind. Use with `below: 1`. |
| `log-count` | Events matching `where` fields exactly, such as `{ 'emails.failed': '1' }`. |
| `metric` | A gauge by `name`, with `agg` `avg` (default), `max` or `latest`, and `attributes` to filter on. |
| `new-error` | Errors whose cause was never seen before. |
| `slo-burn` | How fast an [objective](/docs/definitions/catalog) uses its error budget: `{ source: 'slo-burn', slo: 'shipping' }`. |
| `rule-violation` | Breaches of a [production rule](/docs/definitions/catalog): `{ source: 'rule-violation', rule: 'checkout-queries' }`. |
| `sql` | Any query, see below. |

## Your own query

`sql` runs a ClickHouse query and uses the `v` of the last row as the value. It must return `t` (a time in milliseconds) and `v`. Return one row for the whole window, as below, so the value is not a half-filled bucket. Four parameters are filled in for you: `{from:String}` and `{to:String}` (the window), `{env:String}` and `{step:UInt32}` (the window in seconds, for charts that bucket by it).

```ts
export const refusedShipments = defineAlert({
  id: 'refused-shipments',
  name: 'Parcelo refuses shipments',
  family: 'Providers',
  when: {
    source: 'sql',
    sql: `SELECT toUnixTimestamp(now()) * 1000 AS t, count() AS v
          FROM logs
          WHERE Timestamp >= toDateTime64({from:String}, 3) AND Timestamp <= toDateTime64({to:String}, 3)
            AND Environment = {env:String} AND TaskKind = 'parcelo.ship' AND Outcome = 'failed'`,
  },
  above: 10,
  window: '30m',
})
```

## When it fires

| Field | What it does |
|---|---|
| `above`, `below` | A fixed threshold: fire when the value is above, or below, it. |
| `sigma` | Fire when the value is that many standard deviations above its own last 7 days, instead of a fixed threshold. It needs at least 24 windows of history, and says so until it has them. |
| `window` | The time the value is computed over: `30s`, `10m`, `2h`, `1d`. |
| `for` | How long it has to hold before firing, in the same units. |
| `quiet` | Hours when it keeps recording but holds the notification until they end. |
| `notify` | One channel by name (a channel from **Settings** or a [`defineChannel`](/docs/definitions/more#channels)). Without it, every channel. A name that no longer exists falls back to every channel: an alert never goes silent. |
| `family`, `unit`, `condition` | The group the alert is listed under, the unit written after its value (`%`, `ms`, `s`), and one sentence that says what it checks. |

Alerts that fire within 30 seconds of each other go out as one message, with the errors behind them and what to do. See [Alerts and notifications](/docs/features/alerts).

Two things to know:

- Alerts watch **one environment**: the first of `VIGIE_ENVS` (production on a server), or the one named by `VIGIE_ALERT_ENV`. Staging noise never wakes anyone.
- An alert in code is owned by its file. Keep its `id` stable: if you remove it from the code, it is deleted from Vigie.
