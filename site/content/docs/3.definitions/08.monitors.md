---
title: Monitors
description: defineMonitor checks a URL every minute and opens an outage after two failures in a row.
---

```ts [definitions/monitors/acme.ts]
import { defineMonitor } from '@vigiejs/sdk'

export const api = defineMonitor({ id: 'api', name: 'API', url: 'https://api.acme.example/ready', expect: 200 })
export const shop = defineMonitor({ id: 'shop', name: 'Shop', url: 'https://shop.acme.example' })
```

`expect` is an exact status. Without it, anything under 400 counts as up. Redirects are not followed, so a `301` counts as up unless you set `expect`. A check that gets no answer in 10 seconds fails.

Two failures in a row open an outage and send a message to your [notification channels](/docs/features/alerts#channels). The first success closes it, with a second message. The **Uptime** screen shows each check and outage.

Monitors in code only run in server mode, so a laptop never probes production. Monitors can also be added on the **Uptime** screen. The `id` is how a [status page](/docs/definitions/status-page) refers to it (`monitor:api`), so keep it stable.

::warning
Vigie cannot report its own host going down. Keep one check on Vigie itself from somewhere else.
::
