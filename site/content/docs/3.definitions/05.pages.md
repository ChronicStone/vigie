---
title: Pages
description: definePage adds a screen of your own to the nav, built from SQL blocks, and an MCP tool that reads it.
---

```ts [definitions/pages/invoxa.ts]
import { definePage, eventList, funnel, row, series, stateLine, table, ui } from '@vigiejs/sdk'

const sync = `FROM logs WHERE $__timeFilter(Timestamp) AND Environment = $__env AND TaskKind LIKE 'invoxa.%'`

export default definePage({
  id: 'invoxa',
  title: 'Invoxa',
  nav: { group: 'Background', order: 30 },
  process: 'billing-sync',
  layout: [
    stateLine({
      sql: `SELECT countIf(Outcome != 'succeeded') AS failed, count() AS total ${sync}`,
      text: (r) => (r.failed / Math.max(r.total, 1) > 0.05 ? ui.text('Invoxa sync is failing', { tone: 'error' }) : ui.text('Invoxa sync is healthy.')),
    }),
    funnel({
      title: 'Invoxa sync, from start to finish',
      steps: [
        { label: 'Customers sent', sql: `SELECT uniqExactIf(TaskId, TaskKind = 'invoxa.customer.sync') AS n ${sync}` },
        { label: 'Invoices sent', sql: `SELECT uniqExactIf(TaskId, TaskKind = 'invoxa.invoices.sync' AND Outcome = 'succeeded') AS n ${sync}` },
      ],
    }),
    row(
      table({ title: 'Why it fails', sql: `SELECT LogAttributes['taskOutcome.reason'] AS code, count() AS attempts ${sync} AND Outcome != 'succeeded' GROUP BY code ORDER BY attempts DESC LIMIT 10` }),
      series({ title: 'Attempts', kind: 'bars', sql: `SELECT $__bucket(Timestamp) AS t, countIf(Outcome = 'succeeded') AS ok, countIf(Outcome != 'succeeded') AS error ${sync} GROUP BY t ORDER BY t` }),
    ),
    eventList({ title: 'Failed attempts', where: { 'task.integration': 'invoxa', outcome: 'failed' }, limit: 12 }),
  ],
})
```

The page appears in the nav under **Background**, as **Invoxa**. `nav.group` is one of `Investigate`, `Background`, `Reliability`, `Customers` or `System` (without a `nav`, the page goes under Background), and `order` sorts it among the pages of that group. `process` is the id of a [process](/docs/definitions/processes): the page gets an **Open process** button.

## Blocks

| Block | Shows |
|---|---|
| `stateLine({ sql, text })` | One sentence from the first row of a query. `text` receives that row and returns a `ui` block. |
| `stat({ title, sql, unit?, tone? })` | The first value of the first row, as a number. `tone: 'error'` or `'warn'` colours it when it is not zero. |
| `series({ title, sql, kind?: 'bars' \| 'lines' })` | A time series. Name the bucket column `t` (use `$__bucket(Timestamp) AS t`); every other column is a series. In `bars`, a column named `error`, `failed` or `errors` is drawn red. |
| `table({ title, sql })` | Rows of a query. Columns empty on every row are left out. |
| `funnel({ title, steps })` | Each step is `{ label, sql, note?, bad? }`, and its query returns one number. `bad: true` colours it as a loss when it is not zero. |
| `eventList({ title, where, limit? })` | The latest wide events whose fields equal `where`, such as `{ 'task.integration': 'invoxa', outcome: 'failed' }`. A value can be `{ gt: 500 }` for "above". |
| `row(...blocks)` | Side by side, in equal columns. |

The page opens with the state line (only the first `stateLine` counts), then the funnels, then the other blocks in order, wherever you wrote them. A `table` that returns no rows, or a `series` with only zeros, is hidden: a quiet day shows a short page, not empty boxes.

## SQL macros

| Macro | Becomes |
|---|---|
| `$__timeFilter(col)` | `col` is inside the time range picked on screen. |
| `$__env` | The environment picked on screen, as a value to compare with `Environment`. |
| `$__bucket(col)` | The bucket of `col`, in milliseconds, sized to the range. Use it as `t`. |

The same macros work in dashboards, in tools and in the **Query console**. Queries are read-only: one `SELECT` (or `WITH`) statement, at most 10,000 rows, 10 seconds. The tables you can read:

| Table | Holds |
|---|---|
| `logs` | Wide events and logs. `LogAttributes` holds every field: `LogAttributes['task.key']`. |
| `spans` | Trace spans. |
| `metrics_gauge`, `metrics_sum`, `metrics_histogram` | Metrics. |
| `req_1m`, `task_1m`, `query_1m`, `edges_5m`, `trace_index` | Per-minute and per-trace rollups, cheap to scan over long ranges. |
| `events`, `requests`, `task_attempts`, `queries`, `provider_calls` | Views over the above, with named columns. |
| `task_mirror`, `switch_changes` | Copies of your app's task and switch tables, when the app database is connected. |

The **Query console** in Vigie lists the columns of each. Every page is also an MCP tool named `page_<id>` (`page_invoxa` above), so an agent reads the same numbers and tables.
