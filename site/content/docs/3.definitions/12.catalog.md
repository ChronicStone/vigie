---
title: Catalog
description: defineCatalog names your providers and task kinds, and sets objectives and production rules.
---

```ts [definitions/catalog/acme.ts]
import { defineCatalog } from '@vigiejs/sdk'

export default defineCatalog({
  lateAfterSeconds: 300,
  retryLadder: ['1 min', '5 min', '30 min', '2 h', '6 h'],
  providers: {
    'api.parcelo.example': 'Parcelo',
    'api.paynest.example': 'Paynest',
    'api.postwing.example': 'Postwing',
  },
  tasks: {
    'parcelo.ship': { integration: 'parcelo', concurrency: 4, handler: 'parcelo/handlers/ship.handler.ts' },
    'paynest.scan': { integration: 'paynest', every: '5m', clock: 'Every 5 min' },
    'billing.invoices.overdue': { at: '03:00', clock: 'Daily at 03:00' },
  },
  slos: [
    {
      id: 'shipping',
      name: 'Shipments succeed',
      objective: 98,
      good: `SELECT sumIf(Attempts, Outcome = 'succeeded') AS v FROM task_1m WHERE Minute >= toDateTime($__from) AND Minute < toDateTime($__to) AND Environment = $__env AND TaskKind = 'parcelo.ship'`,
      total: `SELECT sum(Attempts) AS v FROM task_1m WHERE Minute >= toDateTime($__from) AND Minute < toDateTime($__to) AND Environment = $__env AND TaskKind = 'parcelo.ship'`,
    },
  ],
  rules: [
    { id: 'checkout-queries', name: 'Checkout runs at most 20 queries', entry: { method: 'POST', route: '/orders/:id/checkout' }, atMost: 20 },
    { id: 'ship-once', name: 'parcelo.ship calls Parcelo once per attempt', entry: { taskKind: 'parcelo.ship' }, host: 'api.parcelo.example', exactly: 1 },
  ],
})
```

| Field | What it does |
|---|---|
| `providers` | Host to name, for **External calls** and provider health. |
| `tasks` | Per task kind: its `integration` (a provider id, as in the `integration` you send), its schedule (`every: '5m'` with `s`, `m` or `h`, or `at: '03:00'` for a daily run, and `clock` for the words shown on screen), `concurrency`, a `serial` key, a feature `switch`, and a `handler` file for "open in code". The schedule feeds **Schedules**: next run, last run and failures in a row. |
| `switch` | The key of the feature flag that turns this kind on or off in your app. Vigie reads its state and history from your app's database (`VIGIE_APP_DATABASE_URL`), and shows held tasks. |
| `lateAfterSeconds` | A due task waiting longer than this counts as late. 300 by default. |
| `retryLadder` | The delays your queue retries with, shown on each run. |
| `slos` | An objective in %, over the last 30 days, from a `good` and a `total` query that each return `v`. Use `$__from`, `$__to` and `$__env` in them. Burn rate shows on **Overview**, and an alert can watch it with `source: 'slo-burn'`. |
| `rules` | Production rules checked on real traffic. Breaches show on **Rules**. See below. |

`defineSlo` and `defineRule` add one at a time, from any file.

## Production rules

A rule counts something inside each request or task, and flags the ones that go over:

| Field | What it does |
|---|---|
| `entry` | What is checked: `{ method, route }` for a request (either can be left out), `{ taskKind }` for a task, or `{ any: true }` for every request. |
| `atMost` | A limit: more than this many is a breach. |
| `exactly` | An exact count: any other number is a breach. Use it instead of `atMost`. |
| `statement` | Count only database queries containing this text. |
| `host` | Count only calls to this host. |
| `aiCalls` | Count only calls to an AI model. |

Without `statement`, `host` or `aiCalls`, it counts every database query. A rule starts as unchecked until traffic reaches its entry. Breaches keep a sample trace to open.
