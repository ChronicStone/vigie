---
title: Quickstart
description: Run Vigie on your machine with one command, then connect an app.
---

You need [Bun](https://bun.sh). Nothing else: Vigie finds or fetches its own ClickHouse.

## 1. Run Vigie

```bash
bunx @vigiejs/cli --seed
```

You will see:

```text
✓ ClickHouse ready (installed binary)

Vigie is ready on http://localhost:5310
  Definitions  /your/project/definitions
  Adonis       node ace add @vigiejs/adonis
  NestJS       npx @vigiejs/nestjs init
  Anything     OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:4318
```

Open the address it prints. ClickHouse comes from an installed binary, else Docker, else a binary downloaded on the first run. If port 5310 or 4318 is taken, Vigie uses the next free one and says so: use the ports it prints.

`--seed` sends a day of realistic telemetry from a made-up shop called Acme, so every page has something to show. Leave it out to start empty.

On your machine Vigie has no sign-in and only listens on `127.0.0.1`. It loads definitions from `./definitions` (or `./vigie`) in the folder you run it from, or from `--definitions <folder>`.

## 2. Connect your app

::code-group

```bash [Adonis]
node ace add @vigiejs/adonis
```

```bash [NestJS]
npx @vigiejs/nestjs init
```

```bash [Any stack]
OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:4318
```

::

The installers find the Vigie running on your machine, set up traces, write `VIGIE_URL` and `VIGIE_KEY` to `.env`, and send a test event. They print `Vigie received a test event` only once Vigie has accepted it. The test event shows on **Logs** as `<your app> is connected to Vigie`.

## 3. Open a request

Start your app and call any route. Open **Logs** in Vigie: the request is there with its route, status, duration and trace. Click it to see the database queries it ran and the calls it made.
