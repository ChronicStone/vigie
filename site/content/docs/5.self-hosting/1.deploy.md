---
title: Deploy
description: Run Vigie on one server with Docker, publicly with HTTPS or privately on your network.
---

Vigie runs on one server next to its ClickHouse. You need a Linux server with Docker and Compose v2, and about 1.3 GB of memory free: the containers are capped at 350 MB for Vigie and 900 MB for ClickHouse (`deploy/compose.yml`).

## 1. Install

::code-group

```bash [Public, with HTTPS]
git clone https://github.com/ChronicStone/vigie.git && cd vigie
deploy/install.sh --domain vigie.example.com
```

```bash [Private]
git clone https://github.com/ChronicStone/vigie.git && cd vigie
deploy/install.sh
```

::

Replace `vigie.example.com` with your own domain, and point its DNS at the server **before** you run the public install: Caddy asks for the HTTPS certificate on the first start.

The script writes `deploy/.env` with fresh secrets, builds and starts the containers, and prints:

```text
Vigie is running at https://vigie.example.com
First sign-in: create the owner with setup code <code>
Ingest key, shown once: vk_…

Point a service at it:
  OTEL_EXPORTER_OTLP_ENDPOINT=https://vigie.example.com/otlp
  OTEL_EXPORTER_OTLP_HEADERS=authorization=<your ingest key>
```

Keep the ingest key: it is shown once. You can create more on **Settings, Tokens** at any time. The script is safe to run again: it keeps the secrets and the data.

## 2. Sign in

Open your Vigie and create the owner with the setup code. If you lost it, run `docker compose -f deploy/compose.yml exec vigie cat /data/setup-code`. After that, sign-up is closed: invite people from **Settings, Members and access**, or turn on single sign-on with the `VIGIE_OIDC_*` [variables](/docs/self-hosting/configuration#sign-in). Roles are viewer, operator, admin and owner.

## 3. Connect your apps

::code-group

```bash [Adonis]
node ace configure @vigiejs/adonis --url=https://vigie.example.com
```

```bash [NestJS]
npx @vigiejs/nestjs init --url=https://vigie.example.com
```

```bash [Any stack]
OTEL_EXPORTER_OTLP_ENDPOINT=https://vigie.example.com/otlp
OTEL_EXPORTER_OTLP_HEADERS="authorization=vk_…"
```

::

In a terminal, the installers open a page in Vigie where someone signed in allows the app, and the app receives its own key. In CI, pass `--key` with a key from **Settings, Tokens**. Each installer ends by sending a test event: if it says Vigie refused the key, check the key and the URL.

## Public or private

| | Public | Private |
|---|---|---|
| Listens on | 443, through Caddy | `127.0.0.1:4310` (app) and `127.0.0.1:4318` (ingest) |
| You open it at | `https://vigie.example.com` | an SSH tunnel: `ssh -L 4310:localhost:4310 you@server`, then `http://localhost:4310` |
| Apps send to | `https://vigie.example.com/otlp` | `http://<server>:4318`, or `http://<server>:4310/otlp`, once Vigie listens on your private network |

A private install only listens on the server itself. To let apps on other machines reach it, set `VIGIE_BIND` in `deploy/.env` to the server's private or Tailscale address (for example `VIGIE_BIND=100.64.0.12`) and run `deploy/install.sh` again. Never set it to a public address: use the public install for that. Also set `VIGIE_PUBLIC_URL` in `deploy/.env` to the address your team opens (the install writes `http://localhost:4310`), so the links in alert messages work.

## Definitions

Keep `definitions/` in your app's repository and get it onto the server: a git checkout, or a copy in your deploy. Set `VIGIE_DEFINITIONS_DIR` in `deploy/.env` to that folder (the default is the `definitions` folder of the Vigie checkout, which holds the Acme example); it is mounted read-only into the container. After a change, click **Reload** in **Settings, Extensions**, or run `docker compose -f deploy/compose.yml restart vigie`. On your machine, changes apply as soon as you save.

## Upgrade

```bash
git pull && deploy/install.sh
```

Tables and columns are created on start, and nothing is dropped. Back up the state first with [`vigie backup`](/docs/self-hosting/backups). The script rebuilds the image from the checkout and restarts Vigie; the data stays in its Docker volumes.
