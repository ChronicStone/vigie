---
title: Security
description: What Vigie does to keep your telemetry and your app safe.
---

- **Nothing leaves your servers by itself.** Vigie sends no usage data anywhere. It only calls what you set up: your alert channels, an AI provider, GitHub, Linear.
- **Secrets are masked at ingest**, before anything is stored: secret-named fields, tokens in paths, email addresses and card numbers, plus your own [redactors](/docs/definitions/redactors). The Adonis and NestJS packages mask `secretPaths` before data even leaves your app. Metric attributes are not masked.
- **Keys are hashed at rest** and shown once: ingest keys (`vk_`), API tokens (`va_`), MCP tokens (`vm_`) and deploy tokens (`vd_`). API, MCP and deploy tokens are read or write, and an ingest key can be pinned to one environment.
- **Sign-up is closed** after the first owner, who needs the setup code printed by `deploy/install.sh` and in the server's logs. Invitations are single-use links that expire after 7 days. Roles: viewer, operator, admin, owner.
- **ClickHouse has no published port.** Vigie runs as a non-root user, on a read-only filesystem, with no Linux capabilities.
- **Your app's database is read-only.** Vigie connects with a role that cannot write, and refuses raw SQL if that role can read credentials.
- **Actions run as people.** Requeueing a task calls your app's API with the signed-in person's own token, so your app's permission checks still apply. A machine token cannot do it.
- **MCP never returns payloads**, only fields and summaries, after masking.

Found a problem? Open a private security advisory on GitHub rather than an issue.
