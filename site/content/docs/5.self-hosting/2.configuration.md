---
title: Configuration
description: Every environment variable Vigie reads, with its default.
---

On a server, set these in `deploy/.env` and run `deploy/install.sh` again: every variable there reaches Vigie. On your machine, set them in the shell that runs `bunx @vigiejs/cli`.

## Core

| Variable | Default | What it does |
|---|---|---|
| `VIGIE_MODE` | `local` | `server` turns on sign-in, ingest keys and code monitors. The Docker image sets it. |
| `VIGIE_PUBLIC_URL` | `http://localhost:4310` | The address people and apps use. Links in alerts point here, so on a private install set it to the address your team opens, such as your Tailscale name. |
| `VIGIE_DEFINITIONS` | the `definitions` folder of the Vigie install | The folder of your definitions. `bunx @vigiejs/cli` looks for `./definitions` or `./vigie` first, or takes `--definitions <folder>`. With Docker, use `VIGIE_DEFINITIONS_DIR` below. |
| `VIGIE_ENVS` | `DEV` locally, `PRD,STG` on a server | Environments this Vigie keeps. The first is the one alerts watch. |
| `VIGIE_DEFAULT_ENV` | the last of `VIGIE_ENVS` | Where data lands when its environment is unknown or not kept. Never production by default. |
| `VIGIE_DATA_DIR` | `~/.vigie`, `/data` on a server | Where SQLite state, secrets and the disk spool live. |
| `VIGIE_HOST` | `127.0.0.1` locally, `0.0.0.0` on a server | The address Vigie listens on. |
| `VIGIE_UI_PORT`, `VIGIE_INGEST_PORT` | `4310`, `4318` | The app and OTLP ports. `bunx @vigiejs/cli` starts at 5310 and 4318 and takes the next free ones. |
| `CLICKHOUSE_URL`, `CLICKHOUSE_USER`, `CLICKHOUSE_PASSWORD`, `CLICKHOUSE_DATABASE` | `http://127.0.0.1:8123`, `default`, empty, `vigie` | Where telemetry is stored. Set `CLICKHOUSE_URL` locally to use your own ClickHouse instead of the one Vigie starts. |
| `VIGIE_TASK_METRICS` | `vigie.tasks` | Prefix of the two task gauges. |
| `VIGIE_UPTIME` | on | Set to `off` to stop all monitor checks. |

## Ingest limits

The defaults suit one small server.

| Variable | Default | What it does |
|---|---|---|
| `VIGIE_BATCH_ROWS` | `10000` | Rows per write to ClickHouse. |
| `VIGIE_FLUSH_MS` | `1000` | How often queued rows are written. |
| `VIGIE_MAX_QUEUE_BYTES` | 64 MB | Memory for rows waiting to be written. When it is full, ingest answers `429` and exporters retry. |
| `VIGIE_MAX_SPOOL_BYTES` | 256 MB | Disk kept per table while ClickHouse is down. Past it, rows are dropped, metrics first. |

## Your app

| Variable | What it does |
|---|---|
| `VIGIE_APP_NAME` | Your app's name, as shown in buttons and messages. `your app` by default. |
| `VIGIE_APP_URL` | Your app's address, for "open in app" links. |
| `VIGIE_APP_TASKS_URL` | Where your app lists its tasks. Defaults to `<VIGIE_APP_URL>/admin/tasks`. |
| `VIGIE_APP_API_URL` | Your app's API. Task actions (requeue, cancel, run now) call it as the signed-in person, which also needs single sign-on against your app. |
| `VIGIE_APP_DATABASE_URL` | A read-only Postgres role, for the **Database** screen and queued tasks. Create it with `psql "$DATABASE_URL" -v password="'choose-one'" -f deploy/app-readonly.sql`, and run that again after each migration: a new column stays unreadable until then. The role cannot read columns that look like credentials (`password`, `token`, `secret`, `hash`…). Vigie refuses raw SQL if the role can read any. |
| `VIGIE_SOURCE_REPO`, `VIGIE_GITHUB_TOKEN`, `VIGIE_SOURCE_PREFIX` | `owner/repo`, a token, and the folder of the app inside it (`apps/api/`), to show the source behind stack frames. See [Releases](/docs/features/releases). |

## Notifications

| Variable | What it does |
|---|---|
| `VIGIE_SLACK_WEBHOOK` | A Slack channel, without going through Settings. Used when no channel is set up. |
| `VIGIE_SMTP_URL`, `VIGIE_MAIL_FROM` | Email alerts. `VIGIE_MAIL_FROM` defaults to `Vigie <vigie@localhost>`. |
| `VIGIE_ALERT_ENV` | The environment alerts watch. The first of `VIGIE_ENVS` by default; the Docker install sets `PRD`. |
| `VIGIE_ALERT_GROUP_MS` | Alerts within this window go out as one message. `30000` by default. |
| `VIGIE_LINEAR_API_KEY`, `VIGIE_LINEAR_TEAM_ID` | **Create Linear issue** on issues. |

## Sign-in

| Variable | What it does |
|---|---|
| `BETTER_AUTH_SECRET` | Signs sessions. `deploy/install.sh` generates it. If it is missing, Vigie makes one and keeps it in the data folder. |
| `VIGIE_OIDC_ISSUER`, `VIGIE_OIDC_CLIENT_ID`, `VIGIE_OIDC_CLIENT_SECRET` | Single sign-on with any OpenID Connect provider. When it is your app's own sign-in, Vigie can also act on tasks as the signed-in person. |
| `VIGIE_OIDC_NAME` | The name on the sign-in button, "Continue with" and this name. `VIGIE_APP_NAME` by default. |
| `VIGIE_ALLOW_SIGNUP` | `true` lets anyone with the address create an account. Off by default. |

## AI

| Variable | What it does |
|---|---|
| `VIGIE_AI_API_KEY` | Turns on Ask Vigie, explain and search in words. `OPENAI_API_KEY` also works. |
| `VIGIE_AI_BASE_URL` | Any OpenAI-compatible provider. |
| `VIGIE_AI_MODEL` | `gpt-4.1-mini` by default. |

## Docker install only

Set in `deploy/.env`, read by `deploy/compose.yml`.

| Variable | Default | What it does |
|---|---|---|
| `VIGIE_DOMAIN` | none | The domain Caddy gets a certificate for. Set by `install.sh --domain`. |
| `VIGIE_BIND` | `127.0.0.1` | The address the app and ingest ports are published on. A private or Tailscale address lets other machines reach them. |
| `VIGIE_APP_PORT`, `VIGIE_OTLP_PORT` | `4310`, `4318` | The published ports. |
| `VIGIE_DEFINITIONS_DIR` | `../definitions` | The folder of your definitions on the host, mounted read-only. |
| `CLICKHOUSE_PASSWORD` | generated | The password of the bundled ClickHouse. |
