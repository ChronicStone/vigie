---
title: Deploy
description: Run Vigie on one server with Docker, publicly with HTTPS or privately on your network.
---

Vigie runs on one server next to its ClickHouse. You need a Linux server with Docker and Compose v2.

## 1. Install

::code-group

```bash [Public, with HTTPS]
git clone https://github.com/ChronicStone/vigie.git && cd vigie
deploy/install.sh --domain vigie.example.com
```

```bash [Private]
git clone https://github.com/ChronicStone/vigie.git && cd vigie
deploy/install.sh
```

::

Replace `vigie.example.com` with your own domain, and point its DNS at the server **before** you run the public install: Caddy asks for the HTTPS certificate on the first start.

The script writes `deploy/.env` with fresh secrets, builds and starts the containers, and prints three things:

- the **setup code** for the first sign-in;
- the first **ingest key**, shown once;
- the address to give your apps.

It is safe to run again: it keeps the secrets and the data.

## 2. Sign in

Open your Vigie and create the owner with the setup code. After that, sign-up is closed: invite people from **Settings, Members and access**, or turn on single sign-on with the `VIGIE_OIDC_*` [variables](/docs/self-hosting/configuration#sign-in).

## 3. Connect your apps

::code-group

```bash [Adonis]
node ace configure @vigiejs/adonis --url=https://vigie.example.com
```

```bash [NestJS]
npx @vigiejs/nestjs init --url=https://vigie.example.com
```

```bash [Any stack]
OTEL_EXPORTER_OTLP_ENDPOINT=https://vigie.example.com/otlp
OTEL_EXPORTER_OTLP_HEADERS="authorization=Bearer vk_…"
```

::

In a terminal, the installers open a page in Vigie where someone signed in allows the app, and the app receives its own key. In CI, pass `--key` with a key from **Settings, Tokens**.

## Public or private

| | Public | Private |
|---|---|---|
| Listens on | 443, through Caddy | `127.0.0.1:4310` (app) and `127.0.0.1:4318` (ingest) |
| You open it at | `https://vigie.example.com` | an SSH tunnel: `ssh -L 4310:localhost:4310 you@server`, then `http://localhost:4310` |
| Apps send to | `https://vigie.example.com/otlp` | `http://<server>:4318`, once ingest listens on your private network |

A private install only listens on the server itself. To let apps on other machines reach it, set `VIGIE_BIND` in `deploy/.env` to the server's private or Tailscale address (for example `VIGIE_BIND=100.64.0.12`) and run `deploy/install.sh` again. Never set it to a public address: use the public install for that.

## Definitions

Keep `definitions/` in your app's repository and get it onto the server: a git checkout, or a copy in your deploy. Set `VIGIE_DEFINITIONS_DIR` in `deploy/.env` to that folder; it is mounted read-only into the container. After a change, click **Reload** in **Settings, Extensions**, or restart Vigie. On your machine, changes apply as soon as you save.

## Upgrade

```bash
git pull && deploy/install.sh
```

Tables and columns are created on start, and nothing is dropped. Back up the state first with [`vigie backup`](/docs/self-hosting/backups).
